## V12 可选人物电脑队友 [F9]

成品：`dist\Broforce_加一命修改器_V12.exe`。关闭旧修改器，重启游戏后连接 V12。

1. 在“操作玩家”选择队友要跟随的玩家。
2. 在“人物”下拉框或“头像选人”中选择当前存档已解锁的人物。
3. 返回游戏按 **F9**，或点击“生成所选人物为电脑队友”。无需点击“仅切换一次”或“启用锁定”。

生成时记录当前选中的角色，之后改变选择不会改变已生成的队友。可依次选择不同英雄组成小队，全队本关仍最多 4 名。常见近战角色改为接近至近战距离再攻击；原生武器由英雄组件执行，AI 不主动使用特殊技能。

V12 将人物编号与指令序号合并为一次 64 位写入，桥接端再次校验人物范围与当前解锁状态。使用独立 V12 共享区标识，不能复用旧游戏进程中的 V11 桥接。

已通过真实程序集编译、24 项 Python 回归及 AI 模拟，包含头像选角、重复/更换生成角色、旧选择失效、四玩家隔离及近战距离。**尚未逐个英雄进行游戏内实测；特殊攻击机制、变身或多角色英雄可能仍需单独适配。** 诊断日志为 `companion_ai_v12.log`。下面是历史版本记录。

## V10 村民强袭 AI（历史版本）

成品：`dist\Broforce_加一命修改器_V10.exe`。关闭旧修改器、重启游戏后连接 V10，按 F8 重新生成。主窗口“村民强袭 AI”按玩家独立开关，默认开启。

- **主动接敌**：选敌不再要求当前就能射中。搜索横向 448、纵向 192 世界单位内的敌人，并限制在玩家附近；射程外、隔墙、不同高度的目标会成为寻路目的地。玩家站着不动时也会出击。
- **持续快速射击**：射击范围由 192 提高至 288；射击间隔由原模板约 0.333 秒降至 0.12 秒，约为原射速的 2.8 倍。仍由游戏原生武器流程发射，不穿墙命中。
- **扩大活动范围**：离玩家的横纵距离之和超过 256 时返回，回到 112 内再恢复出击；追赶途中可向行进方向射击。候选目标距玩家横向不超过 384、纵向不超过 192。
- **无法接近时换目标**：连续两次移动停滞后，暂时放弃该目标 4 秒，避免长时间追逐同一个不可达敌人。
- **可关闭**：关闭强化恢复原生 AI 和原始射击间隔。游戏文件、英雄命数及存档解锁逻辑未修改。

V9 用户实测日志显示多数时间无可射击目标，并曾产生 fire=True 输入；仅凭该日志不能确认子弹已经发射。V10 将发现敌人和开火判断分开，并恢复原生 FollowerMinion 的 Terrain 遮挡层。`villager_ai_v10.log` 每约 3 秒增加记录：扫描数量、敌方数量、范围内数量、可射击数量、排除原因、主动接敌状态、fire 输入、原生射击计时器及双方坐标。

已通过真实游戏程序集编译、19 项 Python 回归及 AI 模拟场景检查，新增覆盖玩家静止时主动接敌、不同高度寻敌/到位开火、隔墙接近/遮挡解除开火、射速恢复和距离边界。**游戏内实际开火、弹丸命中和复杂地形仍待实测确认。** 建议先站在普通兵附近生成 1 名，确认主动移动并开火后再增加数量。下面 V8/V9 为历史记录。

## 2026-09-08 新增：单次切换人物

主界面和头像选人窗口均提供独立的“仅切换一次”和“启用 / 更换锁定”按钮。
“仅切换一次”只在当前存活角色上执行一次换人；成功后关闭原有锁定，之后死亡复活、救人或切关均遵循游戏正常选角。“启用 / 更换锁定”保留立即切换并持续固定人物的行为。

单次切换支持普通离线单人及本地多人关卡和当前存档已解锁的人物。暂停、死亡、复活或救人过渡期间会拒绝本次请求，需要恢复正常后重新点击，不会延迟到下一条命执行。

适用于本机 Steam 版 Broforce（App ID `274190`，已验证构建 `12964083`）。功能包括：

- 普通模式点击“当前玩家 +1 命”；
- Broforce 位于前台时按 `F6`，当前本地玩家 +1 命；
- 钢铁兄弟模式点击“钢铁兄弟 +1 正常命数”，优先复活最近死亡的角色；没有死亡角色时再加入一个尚未参战的真实角色，同时增加一条命；
- 如果钢铁兄弟存档已经出现“数字有命、可用角色为零”的幽灵命数，新选项会优先补角色进行修复，不再额外增加数字命数；
- 普通本地模式可从当前存档已解锁人物中选择一名并开启“人物锁定”；当前人物会立即切换，复活、救人换角或切关后也会自动切回；
- 人物下拉框会同步显示所选人物的游戏内 HUD 头像，便于快速确认锁定目标；
- 连接后约每 `0.25` 秒实时读取并显示当前本地玩家命数；
- 不提供血量功能；
- 在线房间会被桥接组件明确拒绝，只允许单机或本地游戏。

## 使用方法

1. 通过 Steam 启动 Broforce，并进入单机关卡；
2. 运行 `dist\Broforce_加一命修改器.exe`；
3. 点击“连接 / 重新注入”，界面会开始实时监视当前玩家命数；
4. 普通模式点击“当前玩家 +1 命”，或者回到游戏按 `F6`；
5. 钢铁兄弟模式使用独立的“钢铁兄弟 +1 正常命数”按钮，或回到游戏按 `F7`。快捷键仅在游戏位于前台时生效，每次按下触发一次，长按不会连续加命。
6. 在“人物切换 / 锁定（普通本地模式）”区域用下拉框或“按头像选人…”选择人物，点击“仅切换一次”进行单次换人，或点击“启用 / 更换锁定”持续固定人物。蓝色卡片表示已选人物，已锁定人物另有文字标记；点击“关闭锁定”恢复游戏正常随机选角。

人物列表只显示当前存档已经解锁的普通可玩人物，不会借此永久解锁新人物。人物锁定支持普通模式下 1–4 名本地玩家分别设置；在线房间和钢铁兄弟模式会被明确拒绝，并自动清除锁定目标。钢铁兄弟模式中的人物与死亡/可用名单绑定，强行固定同一人物会破坏命数语义，因此没有绕过这项保护。

头像取自当前已验证游戏构建的 HUD 资源，并已打包进修改器，运行时不需要改写或重新读取游戏文件。当前构建给 `CaseyBroback` 和 `ScorpionBro` 指定的是 `Rambro` 后备 HUD 头像，因此这两项会显示同一头像，人物名称仍会正确区分。

普通加命按钮在钢铁兄弟模式中会被明确拒绝，避免只增加 `hardcoreLives` 而没有增加可出场角色。钢铁兄弟新选项会优先把最近死亡角色从死亡名单移回可用名单；没有死亡角色时使用尚未加入本局的全局已解锁角色。两个来源都不存在时不会修改命数。

从归档旧版切换到本版时，建议先退出并重新启动一次 Broforce。含人物锁定功能的新版桥接和共享状态使用独立的 V4 标识，不会把 V1/V2/V3 监视器的残留状态误认为新版连接。

修改器不会替换或写入 Steam 游戏文件。退出 Broforce 后，加载到该次游戏进程里的桥接组件会自动消失；下次启动游戏需要重新连接。

因为程序会把自制桥接 DLL 加载进本机游戏进程，部分安全软件可能把这种“修改器/注入器”行为当作风险程序拦截。源码和构建脚本都保存在本目录，可自行核对；不要从不明来源替换 EXE 或桥接 DLL。

## 实现与兼容性

普通模式使用游戏程序集中的 `Player.AddLife()`。钢铁兄弟模式的命数同时依赖 `hardcoreLives` 和 `hardcoreModeAvailableBros`。新选项发现死亡角色时，将 `hardcoreModeDeadBros` 的最后一名角色移回可用名单；没有死亡角色时才通过 `HeroUnlockController.FreeBro()` 加入新角色。确认可用名单数量增加后才调用 `Player.AddLife()`；检测到幽灵命数时只补角色。

人物锁定通过 `HeroUnlockController.GetUnlockedHeroes()` 读取当前存档已解锁人物，并通过 64 位位图传给界面。桥接只在关卡运行、`BrosReleased` 为真、玩家存活且出生位置已设置、角色已启用并且不处于复活/救人或登机过渡时调用游戏自身的 `HeroController.ChangeBro()`，随后恢复换人前的实际坐标；如果复活或救人后人物发生变化，会以至少 `0.75` 秒的间隔安全重试，避免在过渡帧连续销毁和重建人物。

修改器将一个小型托管桥接组件加载进 Broforce 的 Mono 运行时，并只用一次窗口消息在 Unity 主线程创建常驻监视组件，随后立即恢复游戏原窗口过程。监视组件约每 `0.25` 秒读取当前启用 HUD 显示的命数和已解锁人物，界面通过共享状态读取结果；加命与人物锁定指令都由组件在正常的 Unity 更新阶段执行。没有使用每次重启都会变化的绝对内存地址。

实时监视不会持续向游戏窗口发送同步消息，也不会在死亡或坐飞机过关的玩家对象切换期间从外部线程读取 Unity 对象。

监视器带有独立心跳，并允许 Unity 在修改器位于前台时继续更新。切换关卡时心跳可能因 Unity 主线程加载而暂停，界面会先进入等待状态，不会在短暂加载中立即重注入；心跳持续停止约 15 秒，或监视组件明确报告已销毁时，才会自动重新建立连接。重建时会清除旧的就绪标记，避免把残留状态误认为新监视器已启动。
