# V14 无敌与补满手雷

日期：2026-11-07。Steam App ID 274190，游戏 build 12964083，桥接程序集版本 14.0.0.0。

## 原生接口与已有实现

先查看了 [Utility Mod 原始源码](https://github.com/alexneargarder/BroforceMods/blob/master/Utility%20Mod/Utility%20Mod/Main.cs) 对 `SetInvulnerable` 的使用，最终以本机 `Assembly-CSharp.dll` 反射读取的 IL 为准，复用现有 Mono 主线程桥接，不引入新的补丁框架。

- `TestVanDammeAnim.SetInvulnerable(float, bool, bool)` 使用 `Max(已有时间, 新时间)`，设置原生 invulnerable 状态，并清除 firedWhileInvulnerable。证据：`combat_invulnerable_api_v14.txt`。
- `TestVanDammeAnim.ResetSpecialAmmo()` 以 `originalSpecialAmmo` 设置虚属性 `SpecialAmmo`，随后调用 `HeroController.SetSpecialAmmo` 刷新 HUD。证据：`combat_ammo_api_v14.txt`。
- 本次没有复制第三方实现。每帧给当前角色续期 0.75 秒，不使用无限时长；停用后交还游戏原生计时，不清零其他来源保护。

## 协议与生命周期

V14 共享区 512 字节，4 个玩家槽，每槽 128 字节。原有 0–80 偏移保持含义，新增：88 无敌请求，96 补给序号，104 无敌状态，112 补给结果。120 为全局客户端心跳，仅位于槽 0。

补给结果由 56 位请求序号和 8 位结果码组成。序号与确认匹配后界面才显示结果；连点等待前一次完成。补给请求不跨死亡或暂停延迟执行，重新安装监视器时消费旧序号。

每帧完成原有人物切换、锁定之后，重新解析当前本地玩家角色。沿用出生完成检查，拒绝未出场、死亡、暂停、救人过渡及在线房间；无敌开关在等待期间保留，允许新角色出场后继续。

界面每 250 ms 更新心跳，正常关闭清零心跳并关闭四名玩家无敌请求。桥接超过 3 秒未观察到心跳变化即清除请求；此检查在游戏主线程恢复执行时进行。短保护按游戏时间自然结束，已有更长保护不被缩短。
