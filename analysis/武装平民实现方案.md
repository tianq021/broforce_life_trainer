# 武装平民生成：静态分析与实现方案

分析日期：2026-09-08。只读取本机游戏程序集并解析 IL，未启动或注入游戏，未修改修改器功能或游戏存档。

程序集：`F:\SteamLibrary\steamapps\common\Broforce\Broforce_beta_Data\Managed\Assembly-CSharp.dll`。项目此前记录的构建为 12964083；本次依据当前文件实际接口分析，未重新确认 Steam 构建号。

## 已确认的调用路径

游戏自身的 `Rogueforce.PerkSystem.Perks.SpawnVillagerAfterKills.SpawnVillager(Player)` 提供了可参考的完整生成流程：

1. 从 `Map.Instance.activeTheme.villager1` 读取预制体。
2. 保留有 `Villager` 组件且没有 `Citizen` 组件的项。
3. 计算玩家附近的坐标，结合地面高度判断是否使用降落伞。
4. 调用公开静态方法 `MapController.SpawnVillager_Networked`，最后一个参数传入玩家编号。

已确认的完整签名与参数名：

```csharp
Villager MapController.SpawnVillager_Networked(
    Villager villagerPrefab,
    float x, float y, float xI, float yI,
    bool tumble, bool useParachuteDelay, bool useParachute,
    bool onFire, bool isAlert, int armedPlayerNum);
```

内部先通过 `Networking.InstantiateSceneOwned` 创建场景对象，再调用该对象的 `SetSpawnState`。方法名称含 Networked 是游戏自身的对象管理方式；修改器仍应以 `Connect.IsOffline` 限定离线运行。

`Villager.SetSpawnState` 在 `armedPlayerNum >= 0` 且对应玩家存活时调用 `ArmVillager(player.character)`。后者会通过游戏 RPC 执行：

- 设置 `playerNum` 为所属玩家编号；
- 切换武装材质，设置 `hasGun`，激活枪械；
- 移除武装交互开关；
- 进入 `VillagerAI` 的随从模式。

`VillagerAI.GetInput` 随后委托 `FollowerMinion` 获取操作输入。`FollowerMinion.FindLeader` 寻找附近玩家，设置 leader / leaderPlayerNo，并调用 `Player.RegisterMinion`。由此确认存在原生随从初始化路径；实际攻击效果、复活后的跟随和清理仍需实测。

## 初始化细节

- `Villager.Awake` 会设置 `isHero=false`、初始 `playerNum=5`，并处理枪械和材质，因此不能只手动写阵营字段。
- `ArmVillager` 在 `hasGun` 已为 true 时直接跳过。优先使用未武装的原生平民预制体；若模板已经带枪，不能假设传入玩家编号就一定完成阵营和随从初始化。
- `SetSpawnState` 在武装后还会写入 xI/yI。建议直接使用生成接口提供的参数，避免重复 ArmVillager 或人工叠加速度。
- 应核对模板具有 VillagerAI、FollowerMinion 和枪械相关资源，发现不兼容模板时拒绝并显示原因。

## 建议第一版行为

按钮“生成武装平民”，快捷键建议 F8，与现有 F6/F7 区分。一次按下生成一名；长按不连发。生成在当前角色身旁，先不做鼠标指定任意位置。

第一版只支持离线且只有一名本地玩家的正常关卡。普通模式和钢铁兄弟模式都可作为测试目标；该操作不需要调用加命、解锁或硬核角色名单接口，但尚不能保证所有间接游戏事件都不影响存档。

执行时检查地图已加载、主题存在、玩家存活、有角色对象且不处于复活/救人过渡。主菜单、死亡等待、加载或乘载具等未验证状态先拒绝，不把请求留到后续关卡补发。

从角色附近左右两侧寻找有支撑且不与地形重叠的位置；找不到则明确失败，后续再考虑空投。游戏原有生成流程会抬高坐标并按高度使用降落伞，不能未经验证直接照搬为“安全落地”。

每次请求在 Unity 主线程执行，建议加短冷却和本功能生成单位的数量上限，防止误操作卡顿。具体冷却和上限属于待实现的产品选择。

## 接入现有修改器

1. GUI 增加按钮、F8 上升沿检测和独立生成请求计数器；仅游戏前台响应快捷键。
2. 桥接共享区目前为 56 字节：建议新增 offset 56 的 8 字节计数器，总长 64 字节。
3. 为避免与旧桥接混用，共享内存、事件、状态文件和程序集版本一起升级到 V5；新旧版切换须重新启动游戏。
4. 在现有 Unity Update 命令消费路径中读取并消费请求，调用独立的平民生成函数；不在窗口消息回调里创建单位。
5. 不直接调用天赋系统的私有 SpawnVillager 方法，而是参考它的模板选择方式，调用公开的 MapController 接口。
6. 返回实例后检查存活、所属玩家和初始化情况；有异步初始化时做有期限的后续确认。界面区分“请求已发送”和“已确认生成”。
7. 日志记录请求编号、玩家编号、模板、位置及失败原因；重连/换关不重放旧请求，清除本功能的场景引用。

## 新存档测试顺序

| 场景 | 检查重点 |
| --- | --- |
| 普通新存档首关，地面上按一次 | 恰好出现一名持枪平民，能移动、跟随并攻击敌人，未变成玩家可操纵角色 |
| 长按、松开后再按、游戏不在前台 | 长按不连发，重新按下生成下一名，后台不生成 |
| 近墙、坡地、平台边缘 | 无卡墙、埋地或无提示的失败 |
| 死亡、复活、救人换角、人物锁定开启 | 过渡期不生成；原随从是否正确重新跟随，有无异常动作或卡死 |
| 乘机甲、切关、过关动画、主菜单 | 未支持状态给出提示；下一关不突然补生成 |
| 不同关卡主题 | 模板存在时正常生成，缺少模板时明确提示，不崩溃 |
| 钢铁兄弟新存档 | 生成前后命数及可用/死亡英雄名单不因本功能直接变化；平民死亡不意外扣玩家命数 |
| 多次生成、全部死亡、退出并重进 | 检查性能、数量限制、场景清理，以及有无意外持久化或存档异常 |

完成后才能把“可通过原生接口实现”提升为“已验证可用”。当前没有实际生成武装平民。
